# Trace records: human direction and machine execution

Each session record has evidence.json (human prompts, answers given through an agent's question dialog with the agent's wording marked as the agent's, and captured comments, with declared redactions), summary.md (human ideas and interventions citing turn IDs), coverage.json (each captured turn covered or explicitly excluded), and checks.jsonl (checks with kind, runner, method, result and artifact).
Sessions making consequential choices add decisions.jsonl: who proposed and selected the choice, the reason it was taken over the alternatives, under what authority, with which human input, the inputs it used, owners, artifacts and evidence.

`trace_record.py keep` runs this routine in one command before each commit of the running session: it finds the transcript as `trace_record.py session` does, refreshes ignored workspace/record-staging/<id>, writes coverage, screens the files, binds the disclosure review, promotes to ai/records/<id>, verifies and writes the commit body with its Record: line and Execution-agent: trailer, and a later commit of the same session updates the same record without renumbering a turn or rewriting a promoted decision or check. It decides nothing that is the agent's: it clears consent only with `--cleared <digest>`, the digest of the captured turns it printed, given after reading every turn and metadata field and only when the local screen finds nothing; it excludes a turn only with `--exclude <turn> "<reason>"` or when the same transcript row is summarized in another promoted record, which it names; and it never writes the summary, a decision or a check. On a session's first capture it names the speaker from git config user.name, unless that reads as a model's name, records the basis, and takes --speaker to name someone else. The Execution-agent: model is the latest model in the session's transcript; a subagent shares its parent's session, so a subagent passes `--execution-agent` with its own model id, and keep records an id the transcript does not name as its latest model as self-reported. When something is missing it names it, promotes nothing and exits 1; it also exits 1 after promoting when verify reports a problem or the commit body is not drafted, and its output says which; when it finds no transcript, the commit goes ahead with a body that says no record was kept and why.
Extract the session transcript with trace_record.py extract to ignored private workspace/record-staging/ (`extract current` for the running Claude Code or Codex session; `trace_record.py session` prints its transcript and model id), passing --speaker only when the speaker's identity is known from the session context; otherwise the speaker stays unknown.
Extract again into the same staging directory whenever the record needs a later turn, in the middle of the session as at its end: the refresh keeps every captured turn, id, redaction, comment and decision, adds the later turns under new ids with the speaker the first extraction named, and resets consent to PENDING.
Read every turn and metadata field, keep the human's own words, redact private and unauthorized third-party material with declared markers, and set consent.third_party_review to cleared in evidence.json only after that review; a clean pattern scan does not replace it.
Clear consent before cover, after the last extract: cover binds evidence.json by its digest, so the order is extract, read and redact, set consent to cleared, write the summary and checks, run cover and privacy-check, resolve uncovered turns, then publication-review --by with the actual reviewer and --scope with the intended audience, promote to ai/records/, and run verify --strict.
Any edit to evidence.json after cover (consent, a redaction, another extract, which also resets consent to PENDING) makes promote refuse with "evidence.json changed since coverage was built"; to recover, run cover again, then privacy-check and publication-review, then promote. The refusal says so.
publication.json binds the disclosure review to all current content files; subsequent changes invalidate it. A disclosure receipt is not independent acceptance or permission to share with another destination.
Follow scripts/INPUT-PROVENANCE.md for the shared passage-annotation interface, safe handling of imported text and disclosure checks. annotate-input distinguishes role from origin, keeps tentative attribution visible, and leaves missing history unknown. The original text remains intact subject to declared redactions.
Use scripts/trace_record.py --help and each subcommand's --help for arguments. The extractors support Claude Code and Codex transcripts; another runner needs a tested extractor or an explicit compatible record.

Capture review comments with `review_inbox.py collect --json` into an ignored packet, then `trace_record.py comments <staging-record> --input <packet>` before resolving them.
Mixed packets retain their nonhuman comments for `checks.jsonl`; the command reports their count and captures the human entries.
Read every added entry, including any raw marker line, for redactions; new inputs reset consent to PENDING.
Use `decision <record> --input <json>` with scripts/decision.example.json as a labelled example; its `type` is one of direction, method, interpretation, implementation, acceptance, transition, correction or other, and `decision --help` and the error for any other value list them. Record a consequential choice when you make it, so its reason is written while it is known rather than reconstructed at the session's end; when evidence.json does not yet hold the turn that directed it, extract again first and cite the id the refresh adds. The account is completed before each commit with the summary, the checks and cover, which keep runs. Name in the optional `inputs` the paths, intake rows (`IN-NNN`) or earlier records (`ai/records/<id>`) the choice used; a present list must name each once. verify reports, as information, where each input and each path in `artifacts` leads: the tree, a commit naming the record, the intake registry, an earlier record, or not found. State in `reason` why the selected choice was taken over the alternatives when you record it; a row without one is recorded as "not stated", never refused, and verify and view count such rows. The default owners are the named humans whose input IDs are cited; explicit owners need owner_authority naming the assignment's source.
Add `--scope "..."` to state which consequential choices the session counts; unlogged decisions are outside that measure.
keep drafts the commit body after verification; to draft one by hand, use `draft-message <record> --subject "..." --out <file>` to assemble the human ideas, agent choices, checks and source references. Inspect it, then use `git commit --file <file>`.
If the record has no captured execution agent, pass `--execution-agent <model-id>` naming the actual executing model, as `trace_record.py session` reads it.
Use `view --out ai/TRACE-VIEW.md` to read the decision account and its coverage. Counts describe recorded selections; unknown history is not zero human or AI involvement.
Fresh coverage manifests bind the input text and decision account with LF-normalized UTF-8 hashes; refresh cover after changing either. Historical records remain readable without an invented backfill.

The unit a person accepts is the trace record. `trace_record.py queue` lists the records with commits that are not currently accepted, returned and refused work included, newest first, labelled `needs you` with its reasons or `routine`, and lists the commits that name no record, each with its subject and who executed it (the first ten, then a count of the rest; `queue --json` carries them all); a record that logs no choice needs you, with the reason "no choices recorded", and is never routine. `brief <record-id>` puts one record on one screen from its own files and from git: the human's turns, the recorded choices with their selectors and stated reasons in full, the changes grouped with the lines added to the instruction files and to the manuscript quoted under their own headings, the checks with their checker, what was examined, their limits and their sources in full. A change to `paper/` is said as a change to the manuscript, the shared text the coauthors rely on, and a change to an instruction file as one every later session works under. `queue` prints first a numbered table, one row per record, from the record, git and the registries: the work to accept or return, from the main commit's subject; what hangs on it, its label first; what the agent chose, each agent-selected choice as its row states it with the alternative when the row names one; where it comes from; its owners, those the decision rows name, else the speakers of the turns the record cites, said so, else "not stated"; `queue --list` and `queue --json` carry the owners too, `queue --list` is the compact listing, and `brief` opens with the same cells. `accept --record <record-id>` covers exactly that record's commits, takes `--by` from git config user.name with `--person`, and defaults the scope to the brief of that record. The brief names the commit its version runs through; `--through <sha>` with that commit covers only it and its ancestors, keeps the bound on the row, and leaves a commit that landed after the person read the brief waiting; without it the record's commits are read when the decision is recorded. A label triages; `routine` is not approval, and `--range` still reaches any commit range.
`queue` ends with what E is waiting on: fixed ledger rows with no recheck, rows closed by hand (or other than by a sweep) with no recheck, and adoptions with no later-run observation; a fixed row awaiting a recheck labels its record `needs you` and names the fixer and the raiser.
Acceptance is a separate authorized act by a person or an actor independent of production under a named researcher's delegation. Declare the actor kind: accept --person for a person's own decision, --agent for advisory model review, --authorized-by for a delegated decision. A person may say the decision to their agent, naming the record; the agent records it with --person --by the person's name, --recorded-by its own model id, the words in --words, verbatim, and --through the commit the brief showed, and the row stays the person's decision. Without a flag, a model-like name is recorded as model review with the basis "inferred from the name", and any other name is recorded as an undeclared actor and is never acceptance.
--decision is accept, return or refuse. A return or refusal is a recorded decision that leaves the candidate unaccepted; keep the reasoning in a tracked memo as well. The latest decision on a commit stands by its time, not its place in the union-merged acceptances.jsonl; conflicting decisions made in the same second resolve to the stricter (refuse over return over accept), and review-status says so. An actor that executed a covered commit, or that the covered records' decisions name as having selected a choice, declared a person or a delegated actor, is recorded as self-review, never as acceptance; a person's own selection, recorded as a person's, is direction and is not, and so is a selection recorded with no kind under the deciding person's own name (unless the name reads as a model's), which the row notes in `selection_note`. A person's decision over a commit that person typed (its git author, with no execution trailer) stays the person's decision, names those commits as own_work, and review-status counts them as the person accepting their own work. --independence records the production roles the actor considered; the tool compares execution trailers and the recorded selectors ignoring case, a trailing bracketed suffix and a trailing date, and cannot see who proposed the work.
A delegated decision records criteria, evidence, objections, the decision, the independence declaration and the authorization's words, verbatim, in --authority; the named researcher remains accountable. A delegated decision recorded without those words reads "authority not stated" and is advisory, as an agentic review run without them is; rows written before the field existed read as before.
Record outside material entering the project with trace_record.py intake, including what was checked before use and, with --version, the material's version beside its digest. The row names who decided: --by defaults to git config user.name, and --person, --agent or --authorized-by declares the actor's kind; a name with no flag is recorded as an actor whose kind was not declared. Material refused or returned at entry is recorded with --decision refuse or return, so the registry holds what was turned away as well as what was admitted; the row removes nothing already in the tree. Outside material waits for the decision in incoming/ inside the shared folder (incoming_root in ai/project.json names another folder), not in the project's data, and moves into the data only after an admitting row; a returned or refused version is never copied into the data. The governing-actions report counts the data files added under sources/, the shared-inventory files and the snapshots that no admitting intake row names (a row with no decision, written before intake took one, admits), names one that only a return or refuse row names as returned or refused yet present, and counts what is held in incoming/ by decision, apart from the data; all of it is information.
Record manuscript promotion and default adoption with trace_record.py transition: the object and its digest, the checks referenced, the actor, the authority (a turn ID or a standing instruction), the decision, the destination and the commits covered. A default-adoption row names the later trace record checked under the new default with --later-run when that record already exists. The row records; the named prompt or instruction authorizes.
Records created by the current extractor carry trace-record schema version 2. Their check rows require candidate, criterion and limits; unversioned historical records remain readable as version 1 without invented backfill. Named procedures also record procedure and procedure_version, with defect_ids and recheck_evidence when those links exist, following ai/SKILL-RUN-CONTRACT.md. Promotion refuses a row whose artifact reads as a path and is absent, unless "reference" is "declared". extract writes the digests of the instruction files in force as file state, not proof of what was read.
A check row may name `sources`, the files it compared the candidate with, each by path and sha256; the agentic reviewer writes them from `--source`, and `brief` shows each check's candidate, criterion, checker, what was examined and sources. A source in a snapshot under workspace/snapshots/ is checked against the snapshot's manifest, by `check --source` as by the agentic reviewer, and named with the snapshot's identifier; one that does not verify is recorded by `check` with the reason in `snapshot_unverified`. A check a person says they made is recorded with trace_record.py check --person and their words in --said: the draft is printed back with `not stated` for what they did not say and appended with --confirm.
Use `"reference": "path"` for a literal file path, including filenames with spaces; use `"reference": "declared"` for a non-file reference. Ignored archive paths that are absent from a checkout remain reported as unavailable.
After a failed targeted recheck, `defect_ledger.py mark --fixed` records the repair claim, with its fixer and fix as the current correction that `draft-recheck` reads, while retaining the unresolved or recurred state until a qualifying recheck passes.
A person's return (`accept --decision return`) opens the ledger row from the objection, listing with `--object` each output the person names as reached by the defect, so that the row verifies only when each has its own passing recheck; `defect_ledger.py draft-recheck` writes the recheck's evidence from the row and the checker's words and prints it back before `verify` records it, with unstated fields reading `not stated` and an unstated outcome leaving the state alone; `trace_record.py later-run` adds a later-run observation to an existing adoption row by a declared observer, and no observation means no link.
trace_record.py registries validates the acceptance, intake and transition rows on read, and scripts/trace_report.py reports, per commit since the install baseline and per principle, recorded, missing, not applicable or unknown. Both run inside check_workflow.py.
The report counts each merge once and compares its files with the receiving branch. An invalid registry or Git range produces an execution error rather than a successful status report.
A person using accept without a range includes model-reviewed work not yet accepted. A name in a record does not authenticate an identity.
Fresh projects store their own attribution and acceptance epochs in ai/project.json; setup never copies another project's backlog or acceptance events.
