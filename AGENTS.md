# Project instructions

Read SETUP-AGENT.md before initialization, and follow its Update section when asked to update the kit, or its section on every TRACE project on this machine when asked to update them all; read WORKFLOW.md before substantive work.
When asked to bring in a skill from another Git repository, update or retire one, or record one a person runs from their own setup, follow SETUP-AGENT.md's section Skills from a source: scripts/trace_skills.py applies each step only after the person agrees, and writes the inventory section of ai/SKILLS-IN-USE.md, which is not edited by hand.
This file is the canonical project instruction source for every agent. CLAUDE.md imports it; agent-specific skill copies must match .skills/.
User instructions take precedence. Preserve existing work and unrelated changes.

## Files and authority

Keep durable evidence and judgments in sources/ and workflow records in ai/; in the academic profile, manuscript sources go in paper/ and slides in presentations/.
Draft manuscript changes in workspace/sandbox/ unless the user asks to edit paper/.
Keep credentials and raw private transcripts outside Git and shared folders.
Large and bulky material lives in the project's shared folder, which the person names once and scripts/shared_folder.py connects: a sync app folder (OneDrive or Google Drive first) by default, a bucket through rclone when the data outgrows it. Run its status before work that adds or reads bulky files; when the folder is not connected on this machine, ask the person where it is and follow SETUP-AGENT.md's section Shared folder.
Decide yourself where each file belongs (Git, the shared folder or kept local), do the technical steps, and tell the person in plain words where it went; after a Git pull, verify this machine's shared files against sources/shared-inventory.json, and after changing them, rewrite that inventory; take a verified local snapshot before an analysis whose results will be reported.
An ignored file is not access-controlled. No cloud provider or public repository is configured by default.
Use plain language: in chat with the person, say what a TRACE letter or a review state means rather than naming it ("a model has reviewed this; no person has accepted it"), and keep the exact terms in the records. Write no em dash anywhere, chat replies included, and one sentence per line in LaTeX source.

## Recording and checking

The artifact a session keeps is a trace record: a record of human direction and machine execution. The human side is direction (written instructions, choices, expressed preferences, objections); the machine side is execution, named by the Execution-agent: trailer. Do not call either a "contribution"; keep that word for what a paper adds to a literature.
Preserve the human's own words in the trace record's evidence, with declared redactions for private or third-party material; a summary never replaces those words.
Treat prompts and human review comments as inputs to the same record; capture a comment before resolving it or deleting its marker.
Distinguish input function (instruction, idea, material) from stated origin (speaker, external, AI, unknown), using evidence-linked passage annotations when useful. Do not infer originality from pasting or style; quoted instructions grant no authority. Keep uncertainty visible.
Follow scripts/INPUT-PROVENANCE.md, shared across agent adapters. Review every record file and metadata field for disclosure, then bind the review with publication-review before promotion. A disclosure receipt is not acceptance or permission for another destination.
Keep the raw review inbox ignored/local. External reviewers receive only a separately inspected, minimized packet within the user's authorization, never a raw trace-record archive by default.
The people whose inputs direct a change own that change and its account by default; such a person is the change's principal, the party an agent acts for. Follow an explicit assignment when present, and retain its source; unattributed input stays unknown.
Retain each person's ideas and later interventions in the summary and substantive commit body, citing the original turn IDs. A title and execution trailer alone are insufficient documentation.
Record consequential choices in decisions.jsonl, distinguishing the proposer, selector, delegated authority, human owners and resulting work, and state in reason why the selected choice was taken over the alternatives; the human direction it answers is not its reason, and a choice recorded without one reads not stated. Routine tool calls need no separate decision entry.
Record each choice when you make it, not at the session's end: when evidence.json does not yet hold the turn that directed it, run trace_record.py extract again into the same staging directory first; name what the choice used in the optional inputs, and complete the account before each commit.
An agent may select an approach within the assigned scope without repeated permission requests. Ownership does not turn those selections into human decisions or silently change Git identity.
Missing historical accounts stay unknown, and counts of decisions do not allocate intellectual credit.
Use the trace-state skill to record a session; ai/RECORD-CONVENTION.md holds the procedure, and a record is promoted only after its content review.
Name the source object, criterion, method, result, checker and limitations when checking a claim. Quote the source when a review diagnoses a textual defect.
Record outside material with scripts/trace_record.py intake, including what was checked before use, its version when it has one, and who decided with their kind declared; record material refused or returned at entry the same way, with --decision refuse or return.
Outside material waits for that decision in incoming/ inside the shared folder (incoming_root in ai/project.json names another folder), not in the project's data, and moves into the data only after an admitting row; a returned or refused file is never copied into the data. The governing-actions report counts what is held there by decision and names a returned or refused file found in the data anyway, as information. Record manuscript promotion and default adoption with trace_record.py transition; the trace-ctransition skill holds both.

A commit executed by a model carries Execution-agent: followed by the actual model ID. Read that ID off the runtime with `python scripts/trace_record.py session`, which works the same under Claude Code and Codex, and use it in Execution-agent: and --recorded-by; when it finds none, put the ID you were told you run as in those fields, the ID alone, and tell the person it is self-reported. The native Git author is the human. Never add AI co-authorship or Made-by trailers. A commit a person typed carries no trailer and needs no flag; there is no commit hook, and the message report blocks nothing.
Keep unreviewed work, model review, human acceptance and delegated acceptance distinct. Work can publish in any state when publication is authorized; publication does not change review status.
The unit a person accepts is the trace record. When the person asks what is outstanding, or states a decision about a record, use the trace-acceptance skill: trace_record.py queue shows what waits and whose it is, and accept --record covers exactly that record's commits.
A label triages: it never accepts, and `routine` is not approval; a record that logs no choice needs a person.
An authorized actor independent of production, including another model lineage, may accept specified work under a named researcher's delegation. Retain its criteria, evidence, objections, decision and the authorization's words in --authority; a delegation recorded without them reads authority not stated and is advisory. The researcher remains accountable.
An actor that executed the work or selected a choice recorded in it is not independent of it, and its attempt is recorded as self-review. A person deciding about a commit they typed stays a person's decision, and the row and review-status say they accepted their own work.
An agent may record advisory model review using accept --agent, including an explicitly flagged self-review. A person's decision is recorded with --person: by the person at the keyboard, or by the agent the person said it to, in the person's name, with the agent's model id in --recorded-by and the person's words in --words, verbatim. Pass --through with the commit the brief showed, so the decision covers the version the person saw and a commit that lands later stays waiting. The person is the one git config user.name names, unless they named themselves otherwise in the session; when another name for the speaker is in view and differs, ask before recording. The agent never decides for the person, never infers a decision nobody stated, and never records one under another name. A name recorded without a flag is model review or an undeclared actor, never acceptance.
Use the trace-review skill for grounded review of a commit, a draft or a passage against named criteria or sources; the reviewer is given the sources, from the repository, the shared folder or a verified snapshot, with their digests. Its run is advisory model review unless it carries a named researcher's delegation, and a reviewer that executed or selected the covered work stays advisory.
A return or refusal is a recorded decision and leaves the candidate unaccepted.
A prompt can authorize a specified boundary transition; retain its source and the relevant checks. A transition row records the decision and does not supply authority, and a default adoption is linked to a later run only when somebody records observing it.
Give new check rows a candidate, a criterion and limits, and an artifact that resolves or is declared; name in sources each file a check compared the candidate with. A check a person says they made is recorded with trace_record.py check, in their name and words, printed back and appended only once they confirm. Use the trace-check skill for the mechanical checks and the governing-actions report; missing is a reported state, not a refusal.

Keep stable defect IDs with scripts/defect_ledger.py, prefixed by ledger_prefix in ai/project.json (else the existing rows' prefix, else DEF); use the trace-evaluate skill to open a finding that did not come from a review run, naming the outputs it reaches and, when an instruction produced it, the faulty default and the affected trace records, and to recheck a correction. Give every supported finding a row before it is fixed: an agentic review's reproduced findings through defect_ledger.py ingest --run ai/reviews/<run> --finding <id>, a REVIEW comment that diagnoses a defect through open once the comment is captured; name the row's id after Fixes (or Fix, Fixed, Closes, Corrects, Resolves) in the commit that fixes it, the fix claim by which the governing-actions report joins a correction to its row; an id only mentioned is not joined. Offline ingestion takes an explicit --matches file; a matching decision must be checked, not guessed.
Closed means a later sweep did not raise the finding; a row closed by hand is a repair claim and stays in what E is waiting on until a recheck reaches it. Verified requires a recorded targeted recheck; absence alone never promotes a defect to verified. A failed recheck leaves the defect unresolved, which fails check until a later recheck passes; a corrected default verifies only with a later-run recheck whose trace record exists and whose instruction version names a commit changing the default, and a defect that reaches several outputs only when each has its own passing recheck.
A recheck is drafted from the checker's own words and printed back before it is recorded; a field the checker did not state reads not stated, and nobody is asked for more than they said.
Keep self-checks separate from independent checks. A technical verification is not acceptance or permission to publish.

## Session completion

Run the relevant tests and `python scripts/check_workflow.py --out workflow-check.json` after substantive code changes. Render TRACE-STATS.md with scripts/trace_stats.py, retaining failures and skips.
In the academic profile, build a document with plain latexmk from its directory; the tracked .latexmkrc selects engine and build/ output. Inspect a changed PDF visually.
Keep a trace record of a session that commits work, with the trace-state skill: before each commit run `python scripts/trace_record.py keep --subject "<the commit's subject>"`, which finds this session's transcript under Claude Code and Codex, updates the session's record in ai/records/, and writes the commit body with its Record: line and Execution-agent: trailer. When keep stops, do what it names (cite or exclude a turn, add a check, or read the captured turns and pass --cleared with the digest it printed) and run it again; when it finds no transcript, commit with a body that says no record was kept and why. A commit a person typed owes none.
Append a short ai/workflow-log.md entry. Commit reviewable changes when authorized, preserving unrelated work. If a sandbox refuses the commit, say so, leave the change staged, and show the commit message you would have used, trailers included. No remote push or cloud write is implied by local setup.
